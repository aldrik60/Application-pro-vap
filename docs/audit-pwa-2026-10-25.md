# Audit PWA : installation, hors connexion, mises à jour, performance

Date : 25 octobre 2026. Périmètre : `public/manifest.json`, `index.html`, `public/sw.js`, enregistrement du service worker (`src/main.tsx`), `vercel.json`, build, polices, parcours notifications. Lecture seule : rien n'a été modifié dans le code (seul `npm run build` a été lancé, il régénère le dossier `dist/`, ignoré par git). Le site en ligne a été interrogé avec `curl`.

## Résumé en 5 lignes

1. Aucun constat BLOQUANT : l'installation, le manifest, les icônes en ligne, les en-têtes de `sw.js` et `index.html` et le découpage du code sont corrects.
2. Le point le plus gênant pour un client : hors connexion ou réseau faible, l'accueil affiche « indiquez votre date d'arrêt » comme si les données étaient perdues (constat A1).
3. Après chaque mise en ligne, une app déjà ouverte peut afficher un écran rouge en anglais avec une trace technique (A2, A3, A4) ; à corriger avant le gel du 29, car chaque correction ultérieure déclenchera ce cas.
4. Notifications : le message « installez d'abord l'app » risque de ne jamais s'afficher sur iPhone (A6, à vérifier), et un abonnement push reste attaché à l'ancien compte après déconnexion (A7).
5. Le site en ligne n'a pas encore les 2 derniers commits (le service worker en ligne est en `v12`, le code local en `v13`) : à pousser avant le test téléphone du jeudi 29.

## Ce qui est déjà bon (vérifié)

- Manifest valide, servi en `application/json`, 5 icônes déclarées, toutes présentes en ligne (192, 512, apple-touch-icon 180, favicon.svg), les 6 mascottes et le logo répondent 200.
- Les `?v=5` sont cohérents entre `index.html`, `manifest.json` et le précache de `sw.js`.
- `index.html` et `sw.js` sont servis avec `Cache-Control: public, max-age=0, must-revalidate` (vérifié en ligne) : un nouveau service worker est détecté à chaque visite.
- Meta iOS présentes : `apple-mobile-web-app-capable`, `-title`, `apple-touch-icon`, `viewport-fit=cover`, `theme-color` clair et sombre.
- En-têtes de sécurité présents en ligne (X-Frame-Options, frame-ancestors, nosniff, Referrer-Policy, Permissions-Policy, HSTS ajouté par Vercel).
- Le service worker ne met pas en cache les réponses d'autres sites (pas de réponses « opaques ») et ne touche pas aux requêtes Supabase en pratique (elles passent sans être stockées).

- Build : 48 fichiers, toutes les pages sont chargées à la demande. Au premier affichage : environ 82 Ko (gzip) pour le code principal + 43 Ko pour Supabase + 9 Ko de CSS. C'est léger.

### A3. Un fichier manquant renvoie la page d'accueil en code 200
- Gravité : AVANT LE 1ER
- Fichier : `vercel.json:2-4`
- Constat vérifié en ligne : `curl https://application-pro-vap.vercel.app/assets/inexistant-abc123.js` renvoie `200` avec `content-type: text/html` (la page `index.html`). La règle `/(.*)` réécrit tout, y compris les fichiers du code.
- Ce que vit le client : après une mise en ligne, un ancien fichier JS n'existe plus ; au lieu d'une erreur 404 propre, le navigateur reçoit du HTML, refuse de l'exécuter (« MIME type text/html »), et le service worker (A4) peut même le garder en cache. C'est la cause racine de A2 après chaque déploiement.
- Correction : ne réécrire que les vraies pages de l'app.
  ```json
  "rewrites": [
    { "source": "/((?!api/|assets/).*)", "destination": "/index.html" }
  ]
  ```
  À tester sur un déploiement de prévisualisation Vercel avant de pousser sur `main` : `/profil` et `/reset-password` doivent toujours s'ouvrir, `/assets/zzz.js` doit répondre 404.

### A5. Le service worker n'a pas de délai d'attente : « wifi sans internet » = écran blanc interminable
- Gravité : AVANT LE 1ER
- Fichier : `public/sw.js:39-51`
- Ce que vit le client : en boutique ou chez lui, le téléphone est connecté au wifi mais sans internet (cas très courant). La requête ne « échoue » pas, elle attend, parfois 30 à 60 secondes, avant que le service worker se rabatte sur sa copie locale. Pendant ce temps : écran blanc. Le mode « réseau d'abord » sans plafond de temps annule l'intérêt du hors connexion dans ce cas.
- Correction : attendre le réseau au plus 4 secondes pour une page (8 pour un fichier JS/CSS), sinon servir la copie locale. Version complète du gestionnaire `fetch` (remplace `sw.js:31-69`, incorpore A4, P4) :
  ```js
  const NAV_TIMEOUT = 4000, ASSET_TIMEOUT = 8000
  const timeout = (ms) => new Promise((_, rej) => setTimeout(() => rej(new Error('timeout')), ms))

  self.addEventListener('fetch', (event) => {
    const req = event.request
    const url = new URL(req.url)
    // On ne touche ni aux POST, ni aux autres sites (Supabase, YouTube, polices), ni à /api
    if (req.method !== 'GET' || url.origin !== self.location.origin || url.pathname.startsWith('/api/')) return

    const isNavigate = req.mode === 'navigate'
    const isHashedAsset = /\/assets\/.+-[A-Za-z0-9_-]+\.(js|css)$/.test(url.pathname)

    if (isNavigate || isHashedAsset) {
      event.respondWith((async () => {
        const cache = await caches.open(CACHE_NAME)
        try {
          const res = await Promise.race([fetch(req), timeout(isNavigate ? NAV_TIMEOUT : ASSET_TIMEOUT)])
          const ct = res.headers.get('content-type') || ''
          if (res.ok && res.type === 'basic' &&
              (isNavigate ? ct.includes('text/html') : !ct.includes('text/html'))) {
            cache.put(req, res.clone())
          }
          return res
        } catch {
          return (await cache.match(req)) ||
                 (isNavigate ? await cache.match('/index.html') : Response.error())
        }
      })())
      return
    }

    // Icônes, manifest, mascottes : copie locale d'abord
    event.respondWith(caches.match(req).then((cached) => cached || fetch(req).then((res) => {
      if (res.ok && url.pathname.startsWith('/assets/')) {
        const copy = res.clone()
        caches.open(CACHE_NAME).then((c) => c.put(req, copy)).catch(() => {})
      }
      return res
    })))
  })
  ```
  Penser à passer `CACHE_NAME` à `provap-cache-v14` pour que cette version soit prise en compte proprement. Test : sur iPhone, couper les données mobiles tout en restant sur un wifi sans internet, ouvrir l'app : l'écran doit apparaître en moins de 5 secondes.

### A7. Notifications : l'abonnement reste attaché à l'ancien compte après déconnexion, et n'est jamais resynchronisé

- Fichiers : `src/contexts/AuthContext.tsx:40-44`, `src/lib/pushNotifications.ts:66-103`, `src/components/NotificationToggle.tsx:22-24`

### A9. Icône « maskable » mal conçue : l'icône sera rognée sur Android

### A10. Les fichiers du code sont revérifiés à chaque ouverture (aucun cache navigateur)
- Gravité : AVANT LE 1ER (petite modification, gain réel sur réseau faible)
- Fichier : `vercel.json:5-15`
- Constat vérifié en ligne : un fichier `/assets/index-xxxx.js` est servi avec `cache-control: public, max-age=0, must-revalidate`. Les noms de ces fichiers changent à chaque modification (hachage) : ils peuvent être gardés un an sans risque.
- Ce que vit le client : à chaque ouverture, le téléphone redemande une dizaine de fichiers au serveur pour savoir s'ils ont changé (aller-retour réseau chacun). Sur 4G faible en boutique, l'ouverture est plus lente que nécessaire.
- Correction (à placer dans `headers`, avant la règle générale) :
  ```json
  { "source": "/assets/(.*)\\.(js|css)",
    "headers": [{ "key": "Cache-Control", "value": "public, max-age=31536000, immutable" }] }
  ```
  Ne pas l'appliquer à `/assets/vap/*.svg` ni à `/assets/logo-*.svg` (noms fixes, voir P2) : le motif ci-dessus ne vise que `.js` et `.css`.

## APRÈS LANCEMENT

### P1. Une app ouverte longtemps ne se met pas à jour
- Gravité : APRÈS LANCEMENT
- Fichier : `src/main.tsx:43-49`
- Ce que vit le client : sur iPhone, l'app reste en mémoire des jours. Aucun contrôle de nouvelle version n'est lancé : il garde l'ancien code jusqu'à une fermeture complète. Après le lancement, chaque correction mise en ligne n'atteindra une partie des clients que plusieurs jours après.
- Correction : à la reprise de l'app, demander au navigateur de vérifier `sw.js`, et proposer un rechargement doux.
  ```ts
  navigator.serviceWorker.register('/sw.js').then((reg) => {
    document.addEventListener('visibilitychange', () => {
      if (document.visibilityState === 'visible') reg.update().catch(() => {})
    })
  })
  // Optionnel : toast « Nouvelle version disponible, Mettre à jour » sur l'événement 'controllerchange'
  ```
  Ne pas recharger automatiquement (risque de perdre une saisie du journal).

### P2. La version du cache est manuelle, les images ne se renouvellent qu'avec elle
- Gravité : APRÈS LANCEMENT
- Fichier : `public/sw.js:1`, `:53-68`
- Ce que vit le client : icônes, manifest, mascottes et logo sont servis « copie locale d'abord », sans date de fin. Si on remplace un fichier SVG de la mascotte sans changer son nom et sans changer `provap-cache-v13`, les clients gardent l'ancienne image indéfiniment. Un changement du seul fichier SVG ne modifie pas non plus `sw.js`, donc le navigateur ne voit aucune nouvelle version à installer. Même règle pour le manifest (`?v=5`).
- Correction : règle de travail simple : toute modification d'une image de `public/` ou du manifest implique de changer `CACHE_NAME` (et `?v=N` pour le manifest et les icônes). À terme, nommer les mascottes avec un numéro de version (`vap-1-premier-jour.v2.svg`) ou injecter automatiquement un identifiant de build dans `sw.js` avec un petit plugin Vite.

### P3. Le cache grossit sans limite
- Gravité : APRÈS LANCEMENT
- Fichier : `public/sw.js:44-46`, `:77`
- Ce que vit le client : chaque mise en ligne crée de nouveaux fichiers JS/CSS (environ 1 Mo au total) qui s'ajoutent au cache ; les anciens ne sont supprimés que quand `CACHE_NAME` change. Au fil des mois, le cache d'un client gonfle (et les adresses de pages avec paramètres, comme un lien de réinitialisation de mot de passe, y sont stockées une par une).
- Correction : après chaque `cache.put`, limiter le nombre d'entrées.
  ```js
  async function trim(cache, max) {
    const keys = await cache.keys()
    for (let i = 0; i < keys.length - max; i++) await cache.delete(keys[i])
  }
  // après cache.put(...) : trim(cache, 120)
  ```
  Ne pas mettre en cache les pages dont l'adresse contient `?` + `code=` ou `token` (lien de réinitialisation).

### P4. Le service worker voit passer toutes les requêtes (Supabase, POST, autres sites)
- Gravité : APRÈS LANCEMENT (corrigé par le code proposé en A5)
- Fichier : `public/sw.js:31-69`
- Ce que vit le client : aujourd'hui rien de cassé, mais chaque appel Supabase (connexion, enregistrement du journal) traverse le service worker pour rien. Un bug futur dans `sw.js` bloquerait toute l'app, connexion comprise. Bonne pratique : laisser passer sans intervenir ce qui n'est pas un GET sur le même site.

### P5. Un clic sur une notification peut ne pas ouvrir la bonne page
- Gravité : APRÈS LANCEMENT (à vérifier sur iPhone, app fermée puis app ouverte)
- Fichier : `public/sw.js:120-137`, en particulier `:129`
- Ce que vit le client : le service worker cherche une fenêtre dont l'adresse « contient » la cible. Pour la notification de 9 h (cible `/`, `daily-push/index.ts:130`) toute adresse du site contient `/` : si l'app est ouverte sur le Journal, le clic remet l'app au premier plan sans aller à l'accueil. Pour un palier (`/badges`) : si l'app est ouverte ailleurs, le service worker ouvre une nouvelle fenêtre. App fermée : `openWindow(url)` ouvre bien l'app sur la cible sous Android ; sous iOS cela fonctionne en principe (16.4+) mais des versions ont ouvert l'app sur la page de départ. À tester.
- Correction :
  ```js
  const target = new URL(event.notification.data?.url || '/', self.location.origin)
  if (target.origin !== self.location.origin) return          // sécurité : même site uniquement
  const all = await self.clients.matchAll({ type: 'window', includeUncontrolled: true })
  const win = all.find(c => new URL(c.url).origin === target.origin)
  if (win) { await win.focus(); if ('navigate' in win) return win.navigate(target.href); return }
  return self.clients.openWindow(target.href)
  ```

### P6. Détails des notifications reçues
- Gravité : APRÈS LANCEMENT
- Fichier : `public/sw.js:90`, `:104`
- Ce que vit le client : (1) `if (!event.data) return` : si une notification arrive sans contenu, aucune notification n'est affichée. Apple exige qu'une notification soit toujours affichée ; après quelques cas, iOS peut supprimer l'abonnement. Les envois actuels ont toujours un contenu, donc risque faible. Afficher un titre par défaut dans ce cas. (2) L'icône `badge` est le logo couleur : sur Android la petite icône de la barre d'état s'affichera en tache grise. Prévoir plus tard une version blanche sur fond transparent. (3) Le badge numérique de l'icône (`setAppBadge`) n'est jamais envoyé par les deux fonctions serveur et jamais effacé : sans effet aujourd'hui.

### P7. Pages jamais visitées indisponibles hors connexion ; précache un peu lourd
- Gravité : APRÈS LANCEMENT
- Fichier : `public/sw.js:2-18`
- Ce que vit le client : hors connexion, seules les pages déjà ouvertes une fois en ligne s'affichent (leurs fichiers sont gardés à la première visite). Un onglet jamais visité (Parcours, Ressources) donne l'écran d'erreur (A2). À l'installation du service worker, 7 images (environ 220 Ko compressés) + 3 icônes (environ 150 Ko, dont `icon-512.png` de 107 Ko qui n'est utile qu'à l'installation) sont téléchargées en même temps que la première page, sur la connexion du client. Acceptable, mais à alléger : ne précacher que l'accueil, `vap-1` et le logo, le reste à la demande (la branche `/assets/` garde déjà ce qui est vu).
- Correction à terme : générer la liste des fichiers du build (plugin Vite) et les précacher tous, pour un vrai mode hors connexion.

### P8. Polices Google : affichage retardé, et une police référencée n'est pas chargée
- Gravité : APRÈS LANCEMENT
- Fichiers : `index.html:19-21`, `src/components/InstallPrompt.tsx:134`, `src/components/NotificationToggle.tsx:300`, `src/index.css:3`
- Ce que vit le client : (1) la feuille de style Google Fonts bloque le premier affichage ; sur un réseau lent, l'écran reste vide en attendant Google. Le service worker ne la garde pas (autre site) : hors connexion, polices de secours et mise en page légèrement décalée. (2) « Cormorant Garamond » est demandée dans le bandeau d'installation et la fenêtre de notifications, mais n'est pas chargée (le commentaire de `index.css:3` date d'une ancienne charte) : le texte « Pro'Vap » et « Restons en contact. » s'affiche en Georgia italique, hors charte (Space Grotesk, Outfit, Marck Script).
- Correction : héberger les 3 polices sur le site (fichiers `woff2` dans `public/fonts/` ou paquets `@fontsource`), déclarer `@font-face` avec `font-display: swap`, précharger la police du corps. Cela supprime aussi un transfert d'adresse IP vers Google : mettre alors à jour `src/pages/LegalPage.tsx:89` et `:128` qui le mentionnent. Pour (2), utiliser `var(--font-display)` ou `var(--font-script)`. Mesure actuelle : 3 familles, dont Outfit en 6 graisses et Space Grotesk en 4 (variables, donc un seul fichier chacun).

### P10. Manifest : couleurs, identifiant, catégories
- Gravité : APRÈS LANCEMENT
- Fichier : `public/manifest.json:8-9`, `:13-17`
- `background_color` et `theme_color` sont sombres (`#1a1a1a`) : au démarrage sur Android en mode clair, l'écran de lancement est sombre puis l'app s'ouvre crème. Le manifest ne gère pas deux thèmes ; choisir la teinte dominante des clients. Ajouter `"id": "/"` (identifiant stable de l'app installée, supprime un avertissement Chrome). Ajouter 2 à 3 `screenshots` (installation plus rassurante sur Android). `categories` contient « medical » : à retirer pour rester cohérent avec le positionnement (l'app n'est pas un dispositif médical), garder `health`, `lifestyle`.

### P11. `vercel.json` : points secondaires
- Gravité : APRÈS LANCEMENT
- Fichier : `vercel.json:5-16`, `:17-19`
- (1) `sw.js` n'a pas d'en-tête explicite : il est bien non mis en cache aujourd'hui (vérifié en ligne) grâce au comportement par défaut de Vercel ; l'écrire noir sur blanc évite une régression future : `{ "source": "/sw.js", "headers": [{ "key": "Cache-Control", "value": "no-cache, no-store, must-revalidate" }] }`. (2) Il n'y a pas de véritable politique de contenu (`Content-Security-Policy` avec `script-src`) : seule la protection contre l'affichage dans un cadre existe. À introduire après le lancement, en mode « rapport seulement » d'abord, car l'app charge Google Fonts, YouTube, Supabase. (3) `/api/keepalive` répond à n'importe qui et interroge Supabase à chaque appel (vérifié en ligne : 200). Sans gravité, mais ajouter un contrôle du secret de cron Vercel (`Authorization: Bearer CRON_SECRET`) pour éviter qu'on le sollicite en boucle (sujet à confirmer avec la relecture sécurité).
